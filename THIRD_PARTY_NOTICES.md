# Third-Party Notices and Provenance Audit

NEXUS-BTC is a unified, offline-first digital-forensics and Bitcoin transaction traffic monitoring platform built in accordance with the NTRO SIH 2026 Problem Statement 5.

This document details the licensing, attribution, and clean-room provenance of all external components, libraries, and reference repositories inspected during the development of NEXUS-BTC.

---

## 1. Clean-Room Provenance & Audited Repositories

During the initial architectural evaluation, six external open-source and hackathon repositories were audited to assess state-of-the-art Bitcoin forensic techniques. **NEXUS-BTC contains zero verbatim copied code from proprietary, unlicensed, or GPL-incompatible repositories.** All algorithmic capabilities (graph construction, Union-Find clustering, motif detection, and fund tracing) were re-implemented from the ground up using a clean-room architectural approach.

| Audited Repository | Upstream License | Provenance & Clean-Room Resolution in NEXUS-BTC |
| :--- | :--- | :--- |
| **Cryptracer** | GPL-3.0 | **Zero code copied.** Cryptracer's Rust/Neo4j graph model and greedy tracing were re-engineered in pure Python using an in-process NetworkX MultiDiGraph and value-aware best-first search. No GPL contagion exists in this codebase. |
| **Elliptic-Bitcoin-Anomaly-Detection** | MIT | Feature engineering concepts (local transaction vs. aggregate neighborhood features) inspired our 14-feature canonical feature engine. Re-implemented using NumPy/Scikit-Learn. |
| **Bitcoin_Fraud_Gnn** | None / Unlicensed | Mathematical graph neural network formulations and node feature formulations were studied. Re-implemented via NetworkX topological feature extraction (PageRank, Katz, in/out-degree ratios) with clean-room isolation. |
| **ElliptiGraph** | Apache-2.0 | Temporal sub-graph partitioning ideas adapted and re-implemented natively inside `app.features.graph_view` and `app.graph.engine`. |
| **SIH-2026-AI-Powered-Monitoring-And-Analysis...** | MIT | Transaction ingestion pipeline concepts adapted into a multi-format (CSV/JSON/XML) quarantine-safe ingestion engine. |
| **SIH26146** | MIT | UI dashboard layouts and Cytoscape styling concepts re-engineered from scratch in React 18/TypeScript with dark-mode tactical forensic styling. |

## 4. Geolocation Data Attribution

NEXUS-BTC includes optional support for offline IP geolocation via MaxMind GeoLite2 or DB-IP Lite databases.

- If GeoLite2 MMDB format is utilized:
  > *This product includes GeoLite2 data created by MaxMind, available from [https://www.maxmind.com](https://www.maxmind.com).*
- If DB-IP Lite MMDB format is utilized:
  > *This product includes IP address data created by DB-IP, available from [https://db-ip.com](https://db-ip.com).*
- **Graceful Degradation:** If no `.mmdb` file is provided in `geo/`, NEXUS-BTC automatically falls back to deterministic relay observation parsing and logs `"Geo enrichment unavailable"` without crashing or degrading core forensic analytics.

## 5. Forensic Identity and Legal Disclaimer

NEXUS-BTC operates strictly under digital-forensics standards:
1. **Network IPs do NOT identify human individuals:** IP addresses recorded in transaction observations represent network relay nodes or P2P broadcast endpoints, not legal identities of wallet holders.
2. **Clusters are Inferred Entities:** Address groupings generated by the Common-Input clustering heuristic and HDBSCAN represent *probable behavioral clusters*, not confirmed legal individuals or corporate entities.
3. **No Fabricated Data:** All metric reports, ROC-AUC, F1, and PR-AUC scores reflect real measured evaluations against synthetic ground truths or local offline datasets.
